# DISCO

**Dynamic Instruction Simulation for Computer Organization**

_"DISCO: An AI-Based Dynamic Instruction Simulation and Performance Prediction System for Computer Organization"_

---

## Purpose

DISCO is a compact, educational **Computer Organization and Architecture (COA)**
project with an **AI/ML** component. It lets a user provide a small CPU workload
(instruction sequence) and a CPU configuration, simulates how that workload
executes on a simplified CPU model, calculates standard COA performance metrics,
and then uses a simple machine learning model to **predict execution time** from
those metrics.

The central idea:

```
Instruction workload
  -> CPU execution (fetch/decode/execute/memory/write-back)
  -> clock cycles
  -> CPI
  -> cache behaviour
  -> execution time
  -> ML prediction
```

DISCO is intentionally small and explainable. It is **not** a real CPU emulator
(no x86/ARM), a compiler, an assembler, or a large AI system.

```
  |

  |-- visualization/plots.py      (tables + graphs)
```

## Features

- Simplified instruction set: `LOAD, STORE, ADD, SUB, MUL, MOV`.
- Educational CPU model with program counter, register file and a full
  **fetch -> decode -> execute -> memory -> write-back** execution trace.
- Simple main memory (read/write) and a **direct-mapped cache** (hits/misses/hit rate).
- COA metric calculation (instruction count, clock cycles, CPI, cache hit rate,
  execution time).
- ML dataset generated by **actually running the simulator** many times
  (no fabricated numbers).
- **Linear Regression** model that predicts execution time from COA metrics,
  reported with MAE and R^2.
- Interactive Streamlit UI with results tables and graphs.

---

## COA Concepts Demonstrated

- Instruction execution and the instruction cycle (stages).
- CPU registers and the program counter.
- ALU-style arithmetic operations (ADD/SUB/MUL).
- Memory access (LOAD/STORE).
- Cache behaviour (hits, misses, hit rate) and its effect on performance.
- Clock cycles and CPI.
- Execution time and its relationship to clock frequency.

---

## Equations

```
CPI            = Total Clock Cycles / Total Instructions

Cache Hit Rate = (Cache Hits / (Cache Hits + Cache Misses)) * 100

Execution Time = Total Clock Cycles / Clock Frequency
```

Unit handling: clock frequency is entered in **GHz**. Since 1 GHz = 1e9
cycles/second:

```
Execution Time (seconds) = Total Clock Cycles / (frequency_GHz * 1e9)
```

Execution time is also reported in **microseconds** for readability.

---

## ML Approach

- **Model:** Linear Regression. 
- **Features:** instruction count, CPI, cache hit rate, clock frequency.
- **Target:** execution time (microseconds).
- **Validation:** train/test split with **Mean Absolute Error (MAE)** and **R^2**.

The AI-based COA concept:

```
CPU simulation -> measurable COA metrics -> ML training -> execution-time prediction
```

The ML model is an enhancement layer over the COA simulation; the simulator
remains the heart of the project.

## How to Run

From inside the `DISCO/` folder:

```bash
streamlit run app.py
```

Then open the URL shown in the terminal (usually http://localhost:8501).

To regenerate the ML dataset directly from the simulator (optional; the app
does this automatically if the CSV is missing):

```bash
python -m analysis.dataset
```

## Example Workload

```
LOAD R1, 10
LOAD R2, 20
ADD R3, R1, R2
MUL R4, R3, R2
STORE R4, 100
```

**Instruction syntax**

| Form                     | Meaning                          |
| ------------------------ | -------------------------------- |
| `LOAD Rd, addr`          | `Rd = MEM[addr]`                 |
| `STORE Rs, addr`         | `MEM[addr] = Rs`                 |
| `ADD Rd, Rs1, Rs2`       | `Rd = Rs1 + Rs2`                 |
| `SUB Rd, Rs1, Rs2`       | `Rd = Rs1 - Rs2`                 |
| `MUL Rd, Rs1, Rs2`       | `Rd = Rs1 * Rs2`                 |
| `MOV Rd, value`          | `Rd = value` (register or int)   |

---

## Expected Outputs

- An **execution trace** table showing each instruction's stages, cache event
  and cycle cost.
- A **register file** view and final program counter.
- A **performance metrics table** (instructions, cycles, CPI, cache hits/misses,
  hit rate, frequency, execution time).
- The **AI predicted execution time**, plus absolute and percentage error.
- Graphs: sample vs execution time, actual vs predicted, cache hit rate vs
  execution time, and clock frequency vs execution time.

---

## Limitations

- Simplified single-cycle-style CPU model; no real pipeline hazard modelling,
  branch prediction, or superscalar execution.
- Cycle costs are educational **simulation assumptions**, not real CPU timings.
- Direct-mapped cache only (no multi-level hierarchy or associativity choices).
- No real ISA, operating system, compiler, or assembler.
- The ML model is a basic Linear Regression intended for explainability.
